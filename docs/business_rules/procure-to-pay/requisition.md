# Business Rules: Purchase Requisition (PR)

## Entity Definition: Requisition
Represents internal purchase demand generated by a department for materials, services, or capital items.

| Field                   | Type                    | Constraint           | Business Rule                                                            |
|:------------------------|:------------------------|:---------------------|:-------------------------------------------------------------------------|
| `id`                    | Long                    | PK, Auto-increment   | Primary identifier inherited from `BaseEntity`.                          |
| `title`                 | String                  | Required             | PR summary title (e.g., `Procurement of Laptops for Q2`).                |
| `note`                  | String                  | Nullable             | Justification or background info.                                        |
| `rejectNote`            | String                  | Nullable             | Required reason if PR is rejected by an approver.                       |
| `currency`              | BigInteger              | Default currency     | Operating currency code/amount.                                          |
| `dueDate`               | Date                    | Required             | Required delivery / fulfillment deadline.                                |
| `investmentId`          | String                  | Nullable             | Capital expenditure project / investment tracking tag.                   |
| `unitPrice`             | BigInteger              | Nullable             | Estimated unit or consolidated cost.                                     |
| `status`                | String (Enum)           | Required             | Lifecycle status (`DRAFT`, `SEND`, `APPROVED`, `REJECT`, `PO_CREATED`).  |
| `budgetDetailId`        | Long                    | Nullable             | Reference to specific `BudgetDetail` line item.                          |
| `budgetDate`            | Date                    | Nullable             | Target accounting date for budget deduction.                             |
| `currentApprovalStage`  | Integer                 | Min 0, Default 0     | Currently active approval level.                                         |
| `totalApprovalStage`    | Integer                 | Min 0                | Total milestone stages required.                                         |
| `lastApproved`          | String                  | Nullable             | User ID/NRP of the most recent approver.                                 |
| `approvals`             | List<Approval>          | JSONB                | Snapshot array of staged departmental approvers.                         |
| `approval`              | Approval                | JSONB                | Temporary purchaser approval object (`temp_purchaser_approval`).         |
| `purchaser`             | Approval                | Nullable             | Dedicated procurement reviewer metadata.                                 |
| `nextApprovals`         | List<String>            | Nullable             | Eligible approvers for the current pending stage.                        |
| `budget`                | Budget                  | ManyToOne            | Associated master budget.                                                |
| `department`            | Department              | ManyToOne, Required  | Originating department.                                                  |
| `details`               | List<RequisitionDetail> | OneToMany, Cascade   | Line items requested.                                                    |

## ✅ Validation & Operational Rules
- `title`, `department`, and at least 1 `RequisitionDetail` item are required to submit (`status = SEND`).
- Submitting the PR copies the approval chain from `Department.approvals`.
- Status transitions: `DRAFT` $\rightarrow$ `SEND` $\rightarrow$ `APPROVED` $\rightarrow$ `PO_CREATED` $\rightarrow$ `CLOSED` (or `REJECT`).
- When a Purchase Order is created from the PR, status becomes `PO_CREATED`.
